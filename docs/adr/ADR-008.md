ADR-008: The Engine Does Not Know Its Surfaces

Status: accepted

Context: Long-term horizon: HTTP API then web interface (freemium), separate projects, possibly separate repos. Risk of UI concerns leaking into the engine.

Decision: Argus's core (ingestion, typing, rules, comparison, storage) depends on no surface. The current CLI is an artisan surface (Max's development/debug tool), not a product surface. The engine exposes operations with clean contracts; no layer "representation for visualization" exists in the engine.

Consequences: The future API will be trivial to add if internal boundaries are clean. The CLI can evolve freely without contaminating the core.
