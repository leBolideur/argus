ADR-003: Rules = Seeded Patterns, Relationships = Instances

Status: accepted

Context: Recurrent confusion between "rule" and "relationship". One component (Pre-Ruler) applies "pre-registered" patterns like "Person + Email in the same line → HAS_EMAIL", while the graph contains concrete links between instances.

Decision:

A rule is a reusable pattern stored in database, at the type level ("when X and Y co-present in a Record → REL_TYPE"). Few rules.
A relationship is a concrete instance between two entities, created by applying a rule. Millions of relationships.
In v0.1.0, rules are seeded by the operator (editable starting ontology in DB). The engine applies them, it does not invent them.
Automatic rule deduction (naming heuristics, types like "boss_mail") is deferred to v0.2: no algorithm can guess the semantics of "boss_mail" (HAS_BOSS_EMAIL? REPORTS_TO? nothing?).
Consequences: The semantic puzzle ("guess the nature of a link") exits the v0.1.0 scope. Direct inheritance: the [[relationships]] section of the old mapping.toml (type, source, target) becomes the seed ontology stored in DB. The TOML file written by the user for each import disappears.
